💡 Architectural Tip

VoxPulse relies on heavy deep-learning workloads. To ensure it loads fast and performs diarization without crashes, we containerized it via **Docker** to easily compile C-libraries (Pango/Cairo) for PDF outputs!

⚠️
Resource Constraint Warning: VoxPulse utilizes deep-learning models. Baseline memory requirements require at least **2GB RAM** (Render Starter Tier, $7/mo). Deploying on Render Free Tier (512MB RAM) will immediately prompt Out-Of-Memory (OOM) compilation failures.

Accept Pyannote Model Terms on Hugging Face

Go to pyannote/speaker-diarization-3.1 and click "Agree and Access Model". This is mandatory for pyannote.audio weights to download.

Generate Hugging Face Write Token

Generate a Read/Write API token under Hugging Face profile settings → Access Tokens. You will paste this as the HF_TOKEN environment variable on Render.

Push VoxPulse to GitHub Repository

Deploying on Render Blueprint requires linking your private or public GitHub repo. Commit the newly generated Dockerfile and render.yaml, and push to main.

Create Render Account

Sign up at dashboard.render.com and link your GitHub account.

📁 Generated Configuration Files

These deployment files have been injected into your root workspace directory.

Dockerfile 
FROM python:3.10-slim

# Prevent python from buffering stdout/stderr (critical for real-time Render logs)
ENV PYTHONUNBUFFERED=1
ENV PYTHONDONTWRITEBYTECODE=1

# Install system dependencies (ffmpeg for audio, pango/cairo for PDF generation)
RUN apt-get update && apt-get install -y --no-install-recommends \
    ffmpeg \
    libpango-1.0-0 \
    libpangoft2-1.0-0 \
    libharfbuzz-0b \
    libjpeg-dev \
    libopenjp2-7-dev \
    libffi-dev \
    shared-mime-info \
    libcairo2 \
    libglib2.0-0 \
    build-essential \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Copy requirements and install python packages
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy the rest of the application
COPY . .

# Expose port (Render sets this dynamically, but Gradio uses it)
EXPOSE 7860

# Run the app
CMD ["python", "app.py"]
render.yaml 
services:
  - type: web
    name: voxpulse
    env: docker
    dockerfilePath: Dockerfile
    plan: starter # Starter plan (2GB RAM) is recommended to prevent OOM
    startCommand: python app.py
    envVars:
      - key: HF_TOKEN
        sync: false # Prompts the user for their Hugging Face token in the UI
      - key: PYTHONUNBUFFERED
        value: "true"
      - key: PORT
        value: "7860"

🗺️ Step-by-Step Operations on Render Portal

Follow these direct steps to provision VoxPulse on the actual Render dashboard.

1

Connect Repository to Render

Log into the Render Dashboard, click the blue "New +" button at the top right, and select "Blueprint".

Connect your GitHub account and select your VoxPulse repository from the list.

2

Configure Blueprint Details

Render will scan the code and automatically detect the render.yaml blueprint file! Configure the following inputs in the form:

  • Service Group Name: voxpulse-group
  • Branch: main (or your current working branch)
  • HF_TOKEN (Hugging Face Token): Paste your secure token (e.g. hf_abc123...)
3

Deploy and Monitor

Click **"Approve"** at the bottom of the page. Render will spin up the virtual machine, fetch the repository code, parse the Dockerfile, install ffmpeg and OS packages, and launch the server.

Once the status changes to green "Live", Render will output the public URL (e.g., https://voxpulse.onrender.com). Open this URL to access your live VoxPulse QA Suite!
